# OA (Operation Agent) 요구사항 정의서

> **프로젝트명**: Operation Agent (오퍼레이션 에이전트)
> **작성일**: 2026-05-13
> **작성자**: 동현
> **버전**: v1.0

---

## 1. 프로젝트 개요

### 1.1 목적
벙커 연료 트레이딩 오퍼레이션 과정에서 외부로부터 수신되는 서류(노미네이션 컨펌, 인보이스, BDR)를 AI 에이전트가 자동으로 파싱·검증하고, 이상이 없으면 자동 발송, 이상이 있으면 담당자에게 알림을 보내는 시스템.

### 1.2 배경
- 현재 우리 회사 오퍼레이션 담당자들이 수작업으로 서류를 확인하고 발송하고 있음
- 외부 메일로 들어오는 PDF/JPG/메일본문 데이터는 신뢰할 수 없어 반드시 내부 데이터와 대조 검증이 필요
- deal_agent(트레이딩 자동화 에이전트) 아키텍처를 참고하여 오퍼레이션 영역에 특화된 에이전트를 구축

### 1.3 참고 시스템
| 시스템 | 역할 |
|--------|------|
| **deal_agent** | 트레이딩 브로커 자동화 에이전트 (아키텍처 참고) |
| **Seanergy Admin** (sp-intra) | 기존 어드민 사이트 - 주문등록, 오퍼레이션, 서류관리 UI |
| **Seanergy Backend API** (port 5105) | 기존 백엔드 API - DB 접근, 주문/서류 CRUD |

## 3. 신뢰 모델

### 3.1 데이터 신뢰도

| 데이터 소스 | 신뢰도 | 역할 |
|------------|--------|------|
| 주문등록 데이터 (DB) | **100%** | 검증 기준 (Ground Truth) |
| 오퍼레이션 수정 데이터 (DDD, 공급일정 등) | **100%** | 검증 기준 (자동 계산값 포함) |
| 외부 메일 PDF | **0%** | 검증 대상 |
| 외부 메일 JPG | **0%** | 검증 대상 |
| 외부 메일 본문 | **0%** | 검증 대상 |

### 3.2 AI 권한

| 권한 | 허용 여부 |
|------|----------|
| 메일 수신 읽기 | ✅ 허용 |
| DB SELECT (조회) | ✅ 허용 |
| DB INSERT/UPDATE/DELETE | ❌ 차단 |
| 서류관리 파일 감시 | ✅ 허용 |
| 직접 메일 발송 | ❌ 차단 (검증 통과 시 시스템이 발송) |

## 4. 핵심 워크플로우

### 4.1 전체 흐름

```
서류관리에 파일 도착 (노미컨펌 / 인보이스 / BDR)
    │
    ▼
AI 서버로 전송
    │
    ▼
AI 에이전트가 파싱 (PDF 추출 / OCR)
    │
    ▼
DB 조회 (주문등록 + 오퍼레이션 데이터)
    │
    ▼
대조 검증
    ├─ ✅ 이상 없음 → 자동 발송
    └─ ❌ 이상 있음 → 발송 차단 + 담당자 알림
```

### 4.2 서류별 검증 상세

#### 4.2.1 노미네이션 컨펌 (Nomination Confirmation)

| 항목 | 검증 내용 | 비교 대상 |
|------|----------|----------|
| 선명 (Vessel Name) | 노미컨펌 문서의 선명 ↔ DB 주문 선명 일치 여부 | 주문등록 DB |
| 포트 (Port) | 노미컨펌 문서의 포트 ↔ DB 주문 포트 일치 여부 | 주문등록 DB |
| 공급일정 (Supply Schedule) | 노미컨펌 문서의 공급일정 ↔ DB 공급일정 일치 여부 | 오퍼레이션 데이터 |
| 수량 (Quantity) | 노미컨펌 문서의 수량 ↔ DB 주문 수량 일치 여부 | 주문등록 DB |

**검증 통과 시**: 노미네이션 컨펌 메일 자동 발송
**검증 실패 시**: 발송 차단, 담당자에게 불일치 항목 알림

#### 4.2.2 인보이스 (Invoice)

| 항목 | 검증 내용 | 비교 대상 |
|------|----------|----------|
| 수량 (Quantity) | 인보이스 수량 ↔ BDR 문서 수량 일치 여부 | BDR 문서 |
| 가격 (Price) | 인보이스 단가/총액 확인 | 주문등록 DB |
| 수량 (Quantity) | 인보이스 수량 ↔ DB 주문 수량 일치 여부 | 주문등록 DB |
| 은행 계좌번호 | 송금/수금 은행 계좌번호 일치 여부 | 내부 마스터 데이터 |

**참고**: 인보이스는 회사 내부에서 생성하는 문서이므로, 발행 전 최종 검증 용도

**검증 통과 시**: 인보이스 발송 허용
**검증 실패 시**: 발송 차단, 담당자에게 불일치 항목 알림

#### 4.2.3 BDR (Bunker Delivery Receipt)

| 항목 | 검증 내용 | 비교 대상 |
|------|----------|----------|
| 수량 (Quantity) | BDR 문서의 공급수량 ↔ DB 주문 수량 일치 여부 | 주문등록 DB |

**참고**: BDR은 공급사에서 보내주는 외부 문서

**검증 통과 시**: BDR 확인 완료 처리
**검증 실패 시**: 담당자에게 수량 불일치 알림

## 6. 서류별 처리 프로세스 상세

### 6.1 노미네이션 컨펌

```
[외부 메일 수신] 공급사가 노미네이션 컨펌 PDF 발송
       │
       ▼
[파일 감시] 서류관리 폴더에 파일 도착 감지
       │
       ▼
[파싱] PDF에서 선명, 포트, 공급일정, 수량 추출
       │
       ▼
[DB 조회] 해당 주문의 선명, 포트, 공급일정, 수량 조회
       │
       ▼
[대조 검증]
  ├─ 선명 일치? ─── ❌ → 알림: "선명 불일치: 문서(ABC호) ≠ DB(DEF호)"
  ├─ 포트 일치? ─── ❌ → 알림: "포트 불일치: 문서(부산) ≠ DB(여수)"
  ├─ 공급일정 일치? ── ❌ → 알림: "공급일정 불일치: 문서(3/27) ≠ DB(3/29)"
  └─ 수량 일치? ─── ❌ → 알림: "수량 불일치: 문서(700MT) ≠ DB(800MT)"
       │
       ▼ (모두 일치)
[자동 발송] 노미네이션 컨펌 메일 발송
```

### 6.2 인보이스

```
[내부 생성] 인보이스 문서 생성 (회사 내부)
       │
       ▼
[파싱] 인보이스에서 수량, 가격, 은행 계좌번호 추출
       │
       ▼
[DB 조회] 주문 수량, 가격 조회 + 마스터 은행 계좌번호 조회
[BDR 조회] 해당 주문의 BDR 문서에서 수량 확인
       │
       ▼
[대조 검증]
  ├─ 수량 일치? (vs BDR) ── ❌ → 알림: "수량 불일치 (인보이스 ≠ BDR)"
  ├─ 가격 일치? (vs DB) ─── ❌ → 알림: "가격 불일치"
  ├─ 수량 일치? (vs DB) ─── ❌ → 알림: "수량 불일치 (인보이스 ≠ DB)"
  └─ 계좌번호 일치? ────── ❌ → 알림: "계좌번호 불일치"
       │
       ▼ (모두 일치)
[발송 허용] 인보이스 발송
```

### 6.3 BDR

```
[외부 메일 수신] 공급사가 BDR 문서 발송
       │
       ▼
[파일 감시] 서류관리 폴더에 파일 도착 감지
       │
       ▼
[파싱] BDR에서 공급수량 추출
       │
       ▼
[DB 조회] 해당 주문의 주문 수량 조회
       │
       ▼
[대조 검증]
  └─ 수량 일치? ── ❌ → 알림: "BDR 수량 불일치: 문서(690MT) ≠ DB(700MT)"
       │
       ▼ (일치)
[확인 완료] BDR 검증 완료 처리
```

## 7. 비기능 요구사항

### 7.1 보안
- AI 에이전트는 DB에 대해 **SELECT 권한만** 보유
- 외부 문서 데이터는 절대 신뢰하지 않음 (0% 신뢰 원칙)
- 자동 발송은 검증 통과 시에만 시스템이 수행 (AI가 직접 발송하지 않음)

### 7.2 가용성
- 서류관리 폴더 실시간 감시 (파일 도착 즉시 처리)
- 파싱 실패 시 담당자에게 알림 (수동 처리 필요)

### 7.3 관찰 가능성
- 모든 검증 결과 로깅 (통과/실패, 불일치 상세)
- 검증 이력 조회 가능
